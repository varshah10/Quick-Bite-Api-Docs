QuickBite API

Build the food-ordering experience your users expect.

QuickBite API gives developers the building blocks to discover restaurants, manage carts, place orders, process payments, and track deliveries.

01Introduction

A user opens a food-delivery app, finds a restaurant, adds a meal to their cart, pays, and tracks the order. Several API interactions power that experience behind the scenes.

Discover
Search restaurants and read menus.
Order
Build carts and place orders.
Pay
Create and retrieve payments.
Track
Poll status or receive webhooks.

Who it's for: backend and mobile developers building ordering experiences. Base URL: https://api.quickbite-demo.example/v1

Integration journey

flowchart TB
A[Authenticate] --> B[Find restaurant] --> C[View menu] --> D[Create cart] --> E[Add items] --> F[Place order] --> G[Process payment] --> H[Track order] --> I[Receive webhook]

You authenticate once, then move from discovery to cart to order. Payment is part of order placement. After that, track the order by polling or, preferably, by webhook.

02Quick Start

Make your first API request in 5 minutes. Prerequisite: curl.

Step 1 — Get your API key

Open the demo dashboard and copy a test key. Test keys start with qb_test_.

export QB_KEY="qb_test_51Hx9demo"
NoteNever put keys in client-side code.

Step 2 — Authenticate

Send the key as a Bearer token.

curl https://api.quickbite-demo.example/v1/restaurants?limit=1 \
  -H "Authorization: Bearer $QB_KEY"

A 200 OK confirms the key works. A 401 means INVALID_API_KEY.

Step 3 — Find a restaurant

curl "https://api.quickbite-demo.example/v1/search?q=pizza&city=Bhopal" -H "Authorization: Bearer $QB_KEY"
{"data":[{"id":"rst_8f2a","name":"Napoli Slice","cuisine":"pizza","is_open":true}],"has_more":false}
NoteCheck is_open before building a cart.

Step 4 — View its menu

curl https://api.quickbite-demo.example/v1/restaurants/rst_8f2a/menu -H "Authorization: Bearer $QB_KEY"
{"restaurant_id":"rst_8f2a","items":[{"id":"itm_margherita","name":"Margherita Pizza","price":34900,"currency":"INR","available":true}]}
NotePrices are integers in the smallest currency unit (paise): 34900 = INR 349.00.

Step 5 — Create a cart

curl -X POST https://api.quickbite-demo.example/v1/carts -H "Authorization: Bearer $QB_KEY" \
  -H "Content-Type: application/json" -d '{"restaurant_id":"rst_8f2a"}'
{"id":"cart_41c7","restaurant_id":"rst_8f2a","items":[],"subtotal":0}
curl -X POST https://api.quickbite-demo.example/v1/carts/cart_41c7/items -H "Authorization: Bearer $QB_KEY" \
  -H "Content-Type: application/json" -d '{"menu_item_id":"itm_margherita","quantity":2}'
NoteA cart belongs to one restaurant. Adding an item from another restaurant returns 409 CONFLICT.

Step 6 — Place an order

curl -X POST https://api.quickbite-demo.example/v1/orders -H "Authorization: Bearer $QB_KEY" \
  -H "Content-Type: application/json" -H "Idempotency-Key: 7c1e-demo-0001" \
  -d '{"cart_id":"cart_41c7","payment_method":"pm_test_card_visa","delivery_address":{"line1":"12 MP Nagar","city":"Bhopal","postal_code":"462011"}}'
{"id":"ord_9d3b","status":"created","payment_status":"succeeded","total":69800,"currency":"INR","estimated_delivery_time":35}
NoteSave id. You need it to track the order. estimated_delivery_time is in minutes.

Step 7 — Check the order

curl https://api.quickbite-demo.example/v1/orders/ord_9d3b -H "Authorization: Bearer $QB_KEY"
{"id":"ord_9d3b","status":"confirmed","payment_status":"succeeded","estimated_delivery_time":35}
NotePrefer webhooks over polling in production.

Cancel an order

POST/orders/{order_id}/cancel works while status is created, confirmed, or preparing. Otherwise it returns 409 CONFLICT. Paid orders are refunded.

07Payments

10Edge Cases: Things That Can Go Wrong

The restaurant became unavailable

POST /orders returns 409 CONFLICT. Ask the user to choose another restaurant. The cart stays valid.

Payment succeeded but the response never arrived

Do not retry blindly. Fetch GET /orders/{order_id} if you have the ID. Otherwise resend the original request with the same Idempotency-Key. QuickBite returns the original order.

The same order was submitted twice

Send a unique Idempotency-Key per checkout attempt. Repeats with the same key within 24 hours return the first result and create no new order.

A webhook was not received

Checklist1. Is the URL public HTTPS? 2. Does your server return 2xx within 10 s? 3. Does signature verification use the raw body? 4. Check delivery logs in the dashboard. 5. Fall back to GET /orders/{order_id}.

The API returns 429

Wait for Retry-After seconds. See Rate Limits.

13FAQ

How do I authenticate?Send Authorization: Bearer <key> on every request.
How do I find a restaurant?Use GET /search or GET /restaurants.
Can I cancel an order after payment?Yes, until status is out_for_delivery. Payment is refunded.
What if payment succeeds but the request times out?Retry with the same Idempotency-Key, or fetch the order.
How do I prevent duplicate orders?Always send Idempotency-Key on POST /orders.
How do I test webhooks?Use a test key and the dashboard's “Send test event” button.
How do I handle rate limits?Honor Retry-After and use backoff.
How long are API keys valid?Until revoked. Rotate them regularly.
